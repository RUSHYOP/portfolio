# Insights

Reviews, observations, and lessons — not task tracking (see `worklog.md`).

## 2026-09-14 — Pre-redesign review

- **Latent Framer Motion hazard:** any component that calls `useScroll({ target: ref })` and *then* conditionally returns `null` leaves the ref unhydrated and throws. Rule adopted: gate rendering *before* ref-dependent hooks (see `QuoteSection` → `QuoteSectionContent` split). Worth grepping for on every new scroll-linked component.
- **Seed data ≠ production data:** `data/settings.json` has no `quote1`/`quote2`, which is exactly what surfaced the bug above. Empty-state paths need to be designed, not assumed — the redesign spec makes "chapter hides when its data is empty" an explicit rule.
- **Theme-wipe:** clip-path `circle()` transitions read as ovals on 16:9+ viewports because the circle grows in CSS px against a non-square canvas. Removed rather than fixed — dark-only is coming anyway.
- **ThreeUI reality check:** its components each own a renderer and the npm package bundles Three 0.128 + 0.165 beside our 0.169. Great as *reference source* (MIT), poor as a stack of drop-ins. Hence approach C: port shaders into one scene, import React widgets only where they're isolated (dock).
- **Network:** outbound to Railway's Mongo proxy port is reset after the TCP handshake on this network while HTTPS works — treat production-DB access from this machine as unreliable; keep a local seed path healthy.

## 2026-09-14 — Voyage slices 1–2 review

- **Plan code is a starting point, not evidence.** Of 14 tasks, 9 needed a fix pass, and most Important findings were defects in the plan's own verbatim code (NaN passthrough in `clamp01`, `logClient` able to throw, client-overridable server `ts`, unseeded streaks, uncancelled RAF, missing Lenis mount seed, FPS-probe cascade, light-theme token leak, Space-skip scrolling the page). Independent review after every task earned its cost.
- **Camera framing needs geometry, not taste.** "Star low-right" turned into arithmetic: the launch look-offset had to be big enough to clear the H1 on desktop (~11° right) yet inside a portrait viewport's ~15° horizontal half-FOV. Every future set-piece placement should be checked at both aspect ratios before committing a constant.
- **Two growth curves compound.** Camera approach already magnifies the star ~6×; an intrinsic 0.25→6 `starScale` on top made it fill a third of the frame by 50%. Tuned to 2.4 and let The Pilot's glare deliver the "fills the frame" beat.
- **Dark-only is not a token problem alone.** Pinning CSS variables on `.voyage-root` fixed `var(--…)` reads but not `[data-theme="light"] .x` attribute rules — those needed a forced `data-theme="dark"` plus scoped shields. Removing the toggle in slice 8 makes the shields dead code; keep them until then.
- **three.js `Color.r/g/b` are linear-sRGB** (ColorManagement default since r152). Deriving canvas `rgba()` from them shifts amber to orange-red; bit-unpack the hex instead.
- **macOS case-insensitive FS bites late.** `Telemetry.tsx` beside `telemetry.ts` typechecked for five tasks and only failed when the component was first imported. Never pair a component and helper differing only by case.
- **Idle-park RAF loops carefully.** A literal "reschedule only while dirty" would have re-armed forever on reduced-motion devices because `reset()` sets `dirty` unguarded from `pointerleave`; the guard belongs in the single sink (`draw`), not in each setter.
- **Node tests can't see textures, sprites or DOM** — round point sprites, glow scale, dock spring, Ignition timing and the mobile sheet were all verified only in the browser. The screenshot baselines are the regression net for those.

## 2026-09-15 — Consulting CMS (sub-project 2) review

- **One spec, four collections.** `defineCollection(def)` generates the Mongoose schema, the DTO mapper, CRUD + reorder, the validator and — via the mongoose-free `defs.ts` — the admin UI. Four collections that would each have needed a model, a route trio and a bespoke tab came to ~2k lines of would-be duplication avoided; the payoff is that client and server validate through *the same* function, so they cannot drift.
- **Markdown is sanitised server-side only.** `src/lib/markdown.ts` (marked + a sanitize-html allow-list) runs in the `/work/[slug]` server component; no raw case-study body ever reaches the client. Hrefs survive only if they match `^(https?:|mailto:)` — `allowedSchemes` alone lets relative and anchor links through — so case-study links must be absolute.
- **Resend `batch.send` is all-or-nothing.** A single rejected recipient fails the whole batch: an invalid auto-reply address silently killed the owner notification too. Send the owner notification and the auto-reply as separate calls, or accept that a bad inquirer address costs you the lead.
- **Resend rejects `example.com` recipients** outright, so smoke tests need a real inbox (or the honeypot path, which stores nothing and sends nothing).
- **Resend's dashboard is not a content store.** The API-keys CSV export only holds a key *preview*, and the `Templates` / `Broadcasts` APIs come back empty for this account — email bodies live in code (`src/lib/mail.ts`) as plain text, versioned with everything else.
- **`appendLog` no-ops on Vercel.** The serverless filesystem is read-only, so anything written to `logs/` exists in local dev only. Production observability needs a console mirror (structured JSON to stdout) — file logs are a dev convenience, not the architecture.
- **`mongoose.models.X || model()` never recompiles under Next HMR.** A long-running dev server holds the *first* compiled schema; new fields are silently dropped on write with no error anywhere. Restart `next dev` after every schema edit — and suspect this first when a field "saves" but never comes back.
- **DevTools MCP `resize_page` clamps around ~500px**, so it cannot reproduce a 390px phone. True mobile screenshots need Playwright with a real device viewport; three mobile-only bugs (tab strip not scrolling the active tab into view, row actions clipping past the card, upload row overflow) were only visible there.
- **Published-only is a data-layer property, not a page one.** The public list handler, `getVoyageContent()` and `/work/[slug]` each filter independently; the check that actually proves it is flipping `published` on a real document and watching the list drop to 0 *and* the page 404 — a passing curl against published content proves nothing.

## 2026-09-18 — Slice 3 planning (Approach Vector + Jump)
- **Compute the sticky hold before defining scroll windows.** A `position: sticky; height: 100vh` pin inside a 150vh chapter is stationary for only `150 − 100 = 50vh` — chapterProgress 0→⅓, not the whole chapter. The controller's "dock over the first ~50%" and mobile thirds were wrong on paper; the plan-writer caught it by doing the arithmetic. Rule: hold = section − pin, then place every window inside it (desktop dock by 0.28; mobile needs a shorter 64vh pin to hold to 0.57).
- **Map first, then plan, then adversarially review the plan — each caught things the previous step could not.** The six-reader map found three implemented-but-uncalled hooks (`setSoften`, `setGlare`, the streak curves) that made slice 3 smaller; the critic corrected four map claims; the five-lens plan review found a plan test that could never go green (`arc` for a lone panel) and nine wrong test counts that would have read as clobbered tests to a fresh implementer. None of these needed code to be written first.
- **Non-discriminating tests are the plan's silent failure mode.** "Combines by max" tests probed points where `max`, `+` and a clamped sum all return the same value; every Jump test ran at velocity 0 where `max(a, b) === b`. Before writing an assertion, pick inputs where the correct and the plausible-wrong implementation differ, and compute the expected literal (`chapterAt(0.205).chapterProgress ≈ 0.25`, `jumpGlare ≈ 0.7071`).
- **Big fan-out workflows will hit the Opus session limit mid-run.** A 52-agent plan review (~4M subagent tokens) stopped at 33/52; `Workflow({ resumeFromRunId })` replayed the finished agents from cache and ran only the 19 failures. Design the scoring so a failed verifier counts as "not refuted" (conservative), and keep the script byte-identical on resume so the cache hits.
- **A single native-scroll emit can skip a 25vh chapter entirely.** Lenis's lerp or a fast flick can carry progress from `approach` straight to `orbit`; an edge detector keyed on `chapter.id === "jump"` never fires. Detect crossings by index (`prev < jumpIndex && next >= jumpIndex`), and drive continuous beats off `chapterProgress`, never off the sign-less `velocity` (a slow deliberate scroll must still burst).

## 2026-10-10 — Voyage slice 3 (Approach Vector + Jump)

- **A 100vh sticky pin inside a 150vh section is stationary for 50vh, not 150.** The hold is `section − top − pin height`, and every chapter-progress window has to sit inside it or the animation plays while the block is already leaving the frame. Desktop therefore docks by chapterProgress 0.28 (inside the 100vh pin's 0→⅓ hold), and mobile got a 64vh pin (86vh of hold → 0→0.573) so the one-panel-at-a-time replacement over `[0.04, 0.56]` fits. The browser review added the corollary: when the dock pill covered the mobile panel header, the fix had to be `padding-top: 4.5rem` on the pin, not a `top` offset — `top: 4.5rem` would have shortened the hold and pushed the last panel's window outside it.
- **`max()` is how two drivers share one control.** Glare (`setGlare` × `jumpGlare`), soften (`setSoften` × `approachSoften`) and the streak curves (velocity × hyperspace) all combine by `Math.max`. The slice-1/2 setters and their tests stayed untouched, and both ends of each beat are continuous because neither driver can pull the other down. The one place this was not enough was the *exit*: WarpStreaks' convergence was a per-frame value that dropped from ~0.55 to 0 on the first Orbit frame while the streaks were still ~60 units long, so it became an eased field. Combining by `max` makes the entry continuous; only state makes the exit continuous.
- **Velocity is the wrong clock for a scroll-native beat.** It is instantaneous and sign-less, so a slow deliberate scroll through the Jump would show nothing. `chapterProgress` is the only monotonic 0→1 driver inside a 25vh window, and every hyperspace/flare curve reads it.
- **The whoosh is a one-shot; the letterbox is a time-based hold floored by the band.** The whoosh is a 0.4 s SFX fired once on the crossing edge. The bars are held for `max(900 ms, the rest of the band)`: the 250 ms idle `tick` renews the deadline for as long as the store still reports chapter `jump`. Without that renewal, any pass that takes longer than 900 ms to cross the 25vh band — every arrow-key pass — would lift the bars while the tunnel is still growing; smoke case D (40 px steps) confirmed the bars hold through the band and ≥ 0.9 s past it. The hold runs on `performance.now()` (monotonic, so a wall-clock adjustment cannot strand or skip it); the store's programmatic timeout runs on `Date.now()`. The two clocks are never compared with each other.
- **A chapter-edge detector has to read chapter *indices*, not ids.** One native-scroll emit can carry approach → orbit, and the store never reports the 25vh micro-beat at all. `decideJumpBeat` fires on `prev < JUMP_INDEX && next >= JUMP_INDEX`. In the browser review, all 4 `voyage.jump` log lines were genuine forward crossings, and the backward pass, the CTA sweep, the reload and the deep-link fired nothing.
- **A programmatic `scrollTo` needs a timeout as well as an epsilon, and a no-op guard.** A user wheel/touch that interrupts Lenis leaves the target unreached, so without the 2 s timeout one interrupted CTA click would suppress the beat for the rest of the session. And a `scrollTo` naming the position the reader is already at emits no scroll event, so nothing would ever clear the flag; the store therefore does not arm in that case, and disarms (and emits) any earlier target it replaces. Both `setScroll` and the idle `tick` resolve the deadline. Before the final-review fix only `setScroll` did, and that was *not* harmless: the tick kept re-emitting a stale `programmatic: true` after the timeout, `useJumpBeat` copied it into `prevProgrammatic`, and a later one-emit flick across the band — whose own emit resolved to `false` — was still suppressed by the stale previous flag. Also, `html { scroll-behavior: smooth }` makes the native fallback's `scrollTo` animate rather than land instantly, outside reduced motion.

Findings from the browser review that the bullets above do not cover:
- **No glass had ever blurred.** `voyage.css` declared `backdrop-filter` before `-webkit-backdrop-filter`. lightningcss drops the standard property when the prefixed one follows it, and Chrome ignores the prefixed alias. So no `.glass` panel, nor the dock, had blurred since slice 1, and neither the unit tests nor the slice-1/2 screenshot review caught it, because a translucent panel without blur still looks plausible. The rule for new glass is prefixed first, then standard. To verify blur, read the computed `backdrop-filter` in DevTools rather than judging it by eye. `globals.css:2443-2444` has the same order (outside this slice).
- **Fixing one rendering bug invalidates the constants tuned against it.** Once the glass blurred, the topology graph at `OFFSET_Z = −34` vanished behind the middle panel. It had only ever been visible *because* the blur was broken. Retuned to −24 / `OFFSET_X` −0.9. When a visual bug is fixed, re-check every placement constant that was judged while the bug was live.
- **The static path inherits the animated path's CSS unless told otherwise.** The still-tier mobile stack picked up the animated rules' `flex: 1 1 0` + `overflow-y: auto`, so three 355 px panels were split into 235 px each and clipped mid-sentence. Only the dedicated `mobile-still.png` capture showed it. Every tier needs its own capture.
- **`font-display: optional` makes the first load a different page.** Styrene A misses the first paint, Space Grotesk renders, and the panel titles wrap differently once the font is cached. Baselines are taken in the cached-font state, so a cold-load diff against them will not match.
- **An MCP round-trip is too slow to photograph short-lived states.** A screenshot lands ≈ 1.4 s after the scroll, which is later than the 0.9 s hold plus the 0.45 s bar transition. p23 therefore shows the bars already up. The bars-down state is photographed at p21, where the band renews the hold indefinitely, and the hold timing is proven by sampled state (smoke D), not by a screenshot.
- **DevTools `emulate` with device metrics *does* reproduce a 390×844 phone** (true `mobile`, DPR 3, tier `mid`). This corrects the 2026-09-15 note: it is `resize_page` that clamps at ~500 px, not the DevTools MCP as a whole.
- **Parallel worktrees held up.** Seven tasks were implemented concurrently in isolated worktrees, each independently reviewed. 2 of the 9 code tasks needed a fix pass (Task 3 convergence snap, Task 8 crossfade width + pointer-events), against 9 of 14 tasks in slices 1–2. The branches were merged one at a time in a fixed order (2, 5, 6, 7, 4, 3, then 8), and the suite was green after each merge.

## 2026-10-13 — Voyage slice 4 (Orbit)

- **Derive fractions from a cumulative vh sum; never `start + span / total`.** Computing `end` as `start + span / 1400` leaves a 1-ulp gap at 6 of the 10 chapter boundaries, and `chapterAt`'s fall-through turns that gap into a one-frame teleport to Surface. `end_i` and `start_{i+1}` must be the *same expression*; a `toBe` contiguity test and a one-ulp-below-each-boundary test pin it (the old `toBeCloseTo(…, 10)` could not). The controller's own check confirmed all 11 boundaries bit-exact.
- **Absolute progress literals in tests silently retarget when the chapter table moves.** Eleven tests failed loudly, but another group kept passing while testing a different chapter (the map listed `Topology`, `EnergyOrb`, `WarpStreaks` and four `useJumpBeat` tests, plus a log assertion). `progressAt(id, t)` names a chapter-relative position, and doing the conversion *first*, under the old table, made it a pure refactor with a green bar on both sides.
- **Any state a reader can stop on must be a complete frame: scroll picks a target, time animates to it.** Slice 4 first scrubbed the step panels with telescoping cross-fades (`stepSolo(i) = crossed(i) − crossed(i+1)`), which made "exactly one panel at a time" a theorem — the summed visibility was exactly 1 and `Σ i·stepSolo` equalled the ring's cursor. The theorem was correct and still produced half-faded rest frames, because a scroll-scrubbed fade can always be caught at rest mid-way. The browser review found it first on Approach, a slice-3 behaviour: the user saw panel 1 up, panel 2 ghosted and panel 3 missing (reproduced at chapterProgress 0.12), and Dock / rail / CTA arrivals at `approach.start + 0.001` landed before the scrub window on an empty chapter. The fix on both chapters was the same: scroll only decides a 0/1 target (`panelPose.dock`, `orbitSchedule.stepTarget`) and a CSS transition does the animating. Left scrubbed on purpose: the ring's cursor, Topology's node assembly and Approach's mobile `--solo`; a rest frame can still catch the ring mid-travel (`desktop-crossfade-1-2.png`), but the panel is always complete.
- **Compute the sticky hold before placing windows — again.** 300vh section − 100vh pin = 200vh = cp 0 … 2/3 on desktop, 0 … 0.787 on a 64vh mobile pin; one schedule sized to the smaller hold serves both, because the ring is a single WebGL instance and cannot be media-query-aware. The last panel simply stays lit until the pin releases, so a phone dwells on it for the extra 0.12 and the pin's own release is the panel's exit (a first draft that faded the panels with the ring's envelope left a phone with ~38vh of empty pinned frame; the plan review caught it).
- **Roll after `lookAt`.** `lookAt` rebuilds the quaternion every frame, so `camera.rotateZ` afterwards never accumulates and leaves the view direction (and the star's screen position) unchanged; keeping the bank out of `getCameraPose` kept the never-reverse test and every waypoint invariant blind to it.
- **A ring around a star only occludes itself if it is nearly edge-on.** With the near arc below the disc (what the composition needs) the disc sits *inside* the ellipse and the back arc passes above it; at the plan review's measurement (1440×900) the back arc cleared the disc by ~60 px at 72° and ~25 px at 84°, and occlusion needed ≳ 87°, where the front node would sit on the star. The 3D read comes from the ellipse, the nodes' perspective size and the limb darkening. `RING_TILT` stayed 72° through the browser review.
- **WebGL lines are 1 px.** The ring is a thin torus, not a `LineLoop`; no `Line2` resize plumbing was needed.
- **Capture methodology: poll `scrollY` until it is stable.** The apparent drift in the early captures (scrollY overshooting 1974 → 2503) was a stale Lenis tween fighting the harness's native `scrollTo`, not a page bug. Captures now wait for a stable `scrollY` before photographing. Retakes on a long-lived tab also show the HUD clock capped at `T+ 59:59`.
- **Size a fixed box against the real copy, not the plan's guess.** The desktop panel's 27rem max left ~70 px of dead glass at 1440×900 because the seed steps need ≤ 357 px (now 23rem); the last field's trailing `margin-bottom` alone caused a 5 px internal scroll at 1024×768; and at 390×844 the seed steps overflowed the capped `min(34vh, 18rem)` mobile box by up to 67 px and hid "How long". The mobile fix was a smaller type scale, not a taller box, because the cap is what keeps the star clear.
- **The first entry into a shader-heavy chapter is not the steady state.** On mobile emulation with 4× CPU throttle, steady-state Orbit cost 10.1 ms median against Approach's 9.4 ms, but the first entry after a reload measured 23.7 ms median / p95 40 ms — shader warm-up. Measure the first entry separately; the fix (precompile the ring and `EnergyOrb` programs at scene init with `renderer.compile`) is a slice 8 follow-up.
- **Plan review caught the paper defects; only the browser caught the feel.** Two plan reviews before execution found a Critical and several Important issues (the mobile dwell, a ring "occlusion" cue that never engages, a panel that covered the star, tautological tests); then all eight code tasks were approved on their first review with no fix pass. The two changes that mattered most in this slice — the dock and panel triggers — were visible only on the live page, and one of them was a slice-3 defect that the slice-3 reviews and 413 tests had not seen.

## 2026-10-14 — Voyage slice 5 (Worlds)

- **A longer chapter silently re-times everything keyed to absolute progress — find those consumers before changing the table.** Growing Worlds 225 → 450vh failed exactly one test loudly and shrank the star 10–21 % at Approach and Orbit without failing any: `starScale` / `distanceAU` divided *absolute* progress by The Pilot's start. The fix is to key them by `(chapter, chapterProgress)` (the star clock); the safety net is a golden table captured from the OLD tree at 17 digits *before* touching the table, keyed by chapter, so the new code is held to the old numbers. The browser review then confirmed it in pixels: star size at the slice-4 capture points matched (6.5 px vs 6.5 px at prejump; a wrong clock would have shown about −17 %).
- **Test clearance over the interval a thing is visible, not over the whole path.** The corridor after Worlds passes within ~4 units of where a planet sits, so "keep ≥ R + 3 from the camera" is false over the whole path (the map measured 1.7–4.3) and true over the planet's visible interval (11.7+ measured). `visible = false` after the fade is therefore load-bearing, and the test asserts the visible interval only.
- **Hybrid placement makes composition testable.** Placing a planet from the camera pose at its slot centre plus a camera-basis offset makes its screen position at the dwell an exact projection (tested to 6 decimals through a real `PerspectiveCamera`), and real camera motion supplies the "carried across" feel — landscape drifts right, portrait drops down, which is why the portrait test asserts y, not x. A portrait window ≥ 768 px wide still gets the desktop panel, so it needs its own target (`PLANET_TARGET_PORTRAIT_WIDE`): the phone's centred target sat half behind the panel at 768×1024 and the landscape target would have covered the star.
- **A fixed-height box shared by N overlapping panels is a tuning treadmill; a one-cell grid is not.** On desktop the panels share one grid cell and the box is as tall as the tallest; only the phone needs a fixed cap. The price is dead space under the shorter panels when one case carries a diagram (the cell grew 507 → 556 px in the review) — accepted.
- **A flex column that overflows a clipped box shrinks `overflow: hidden` children to nothing.** The phone panel silently lost its context line until every child got `flex-shrink: 0`. Measure `scrollHeight` vs `clientHeight` in a real browser; a screenshot of one case would not have shown a missing line.
- **A class declared later in the file wins a specificity tie.** `.cta`'s padding and font size beat `.world-panel__link` until the selector was doubled. Check the computed value, not the rule.
- **A hash arrival to an element behind a client-only boot gate cannot work natively — and then three layers were needed.** `/voyage#worlds` landed at the top because `id="worlds"` only exists after `tier` resolves; neither the browser's fragment jump nor Next's post-navigation scroll can find it. Layer 1: a pure hash → progress function plus a one-shot, ref-guarded effect (`useHashArrival`) after the gate, through an immediate mode on the store's scroller (Lenis `{ immediate: true }`; native `behavior: "instant"`, because `auto` defers to the page's `scroll-behavior: smooth`). It must stay programmatic so crossing Jump fires no beat. Layer 2 (`adbe339`): the hook clears the fragment with `history.replaceState(history.state, "", path + search)`, so a late native fragment scroll has nothing to re-apply. Layer 3 (`b4333b8`): even so, one cold dev load kept the hash and landed on the section top (0.35385, every panel dark) because a native fragment scroll — the browser's or the Next router's — ran after our jump; `.chapter--worlds { scroll-margin-top: -1.625vh }` (`HASH_ARRIVAL_EPS` × `VOYAGE_SCROLL_VH`, pinned in `voyageCss`) makes any such scroll land on `start + 0.001` with case 1 lit. **The tradeoff of layer 2:** after arriving, a reload or a copied URL no longer deep-links to `#worlds`; the scroll-margin keeps a *real* fragment scroll correct, but the hash is gone from the URL. Recorded, not fixed.
- **Make the effect depend on a value, not an array.** `SceneRoot`'s GL effect depends on `planetsKey(planets)` (a string) and reads `planetsFromKey(key)`: an inline array prop would rebuild the WebGL context on every `VoyageRoot` render, and keying on the string keeps `exhaustive-deps` honest. `[]` is `""` and `["none"]` is `"none"`, so an empty list never collides with a one-planet list.
- **The only way to test a shader is to compile it in a browser — a 30-line harness is enough.** `esbuild --bundle` the real `Planet` + `EnergyOrb` into one IIFE, serve it with `python3 -m http.server`, call a `window.run(w, h, k)` through the Playwright MCP, read the console and a screenshot. It caught two composition faults no unit test could (a moon eclipsing the star; a ring touching its halo) and was cheap enough to run per tweak.
- **A planet lit from behind is mostly night.** The star sits behind and to the left of every planet, so the visible face is mostly the unlit side; a night floor (`PLANET_NIGHT_FLOOR`) keeps the noise readable and the storm band gets its own faint glow. The amber terminator is the one sanctioned amber outside the star.
- **A guard that does not widen the thing it guards.** The seed guard fails closed (`mongodb+srv`, trailing-dot hosts, mixed host lists, look-alike hostnames) but covers only the new, published placeholders: the existing seed wipes five collections without any guard and still does, now documented. An existing case is validated in `"update"` mode, which writes only the keys the literal lists: a field the literal omits is never rewritten, so a defaulted one an owner edited through `/admin` (`planetFeature`, `published`) keeps its value, where create mode would reset it to the default. (`diagram` has no spec default, so it is untouched in either mode — the placeholders simply omit it; a first draft of this plan claimed create mode would reset an uploaded diagram, and a mutation test showed it would not.) The branch that decides whether published placeholders reach a database lives in a tested function (`seedPlaceholdersIfAllowed`), not inline in the script, and the refusal is announced before the pre-existing wipe, not only after it — an operator who sees `exit=1` must not believe nothing was written. For the browser review only the three placeholders were seeded, through `seedPlaceholdersIfAllowed` from a scratch script: `npm run seed` would also have wiped and reseeded projects, skills, settings, services and steps.
- **`renderer.compile` walks hidden objects** (`scene.traverse`, not `traverseVisible`), so hidden planets and the hidden ring compile up front; it is synchronous on purpose and wrapped so a failure is a logged event, not a throw out of an effect. **It bought nothing visible here:** the A/B at 4× CPU (the call commented out, restored, never committed) gave load long tasks of 105 / 256 / 79 ms with it and 102 / 258 / 56 without, an identical first entry, and slice 4's 23.7 ms first-entry hitch did not reproduce either way (first entry median 8.3 ms, p95 9.1–9.4). Kept as cheap insurance for a real phone GPU; do not credit it with removing the hitch.
- **The plan was applied mechanically before execution.** A small applier script parsed every `Create` / `replace … with` block and every `Run:` command, applied them in order to a pristine worktree and checked the stated test counts; the resulting tree equalled the one the plan was written from. Cheap, and it removes a whole class of "anchor not found" surprises during execution (the task reports record no brief deviation for Tasks 1–7).
- **A 3D fade-in that waits for scroll is a half-built arrival frame — and so is a scrubbed dissolve between two planets.** The panels were 0/1 triggers from slice 4 on, but the planets' fade-in was scrubbed over the first 0.04 of the chapter, so a Dock / rail / back-link arrival at `start + 0.001` showed a lit panel quoting a world that was not there (the planet was already in place and full size, 2 % opacity). That fade-in became a `dt`-eased follower toward a 0/1 target (≥ 95 % within 0.5 s, no overshoot on a huge `dt`, a NaN `dt` is no step). The browser review then found the same fault in the per-planet cross-fade: at rest just past a slot boundary two half-transparent planets overlapped (see-through ghosting), so `da5aee9` replaced the scrubbed `planetWeight` with a per-planet follower toward the panel's own 0/1 `caseTarget`, **staged** so the outgoing planet clears below `PLANET_SWAP_CLEAR` (0.02) before the incoming one rises (`PLANET_SWAP_OUT_RATE` 20, `PLANET_SWAP_IN_RATE`; a whole swap ≈ 0.5 s at 60 fps). Only the last planet's long fade-out (to `PLANET_FADE_OUT_END`) still follows scroll, because it is tied to camera position. The user's ruling extends the standing rule: **anything that dissolves one subject into another is a trigger plus a timed fade; camera motion and placement may still follow scroll.** Retuning `WORLDS_WINDOW[0]` would not have fixed the original arrival frame (it moves the pinned slot centres).
- **A simultaneous cross-fade of two dense panels is unreadable at its midpoint — stage it.** The 0.45 s cross-fade of the two three-column case panels superimposed their text at about 50 % each (and froze that way under the Web Animations API). `b21e3a8` stages it in CSS: the outgoing panel (`[data-solo-off]`) fades out in 0.16 s with no delay, the incoming one fades in 0.32 s after a 0.16 s delay, pinned in `voyageCss`. This is the panel-side twin of the planet swap above.
- **three reports a shader error through a hook, not an exception.** `renderer.compile()` does not throw on a GLSL compile or link error; `renderer.debug.onShaderError` (and `console.error`) is the only signal, so a try/catch alone logs almost nothing. `SceneRoot` sets the hook and logs a truncated info log through the allow-listed `scene.compile_failed` event (`shaderErrorMessage`, pure and tested). The review saw 0 such events.
- **A fixed phone box needs one flexible child, and it must not be the call to action.** The first phone layout made the link the last child of a `34vh` box with fixed-rem content, so any viewport under ~740 px cut it off. `.world-panel__cols { flex: 1 1 0; min-height: 0; overflow: hidden }` makes the excerpts give way instead (measured: link inside the box at 390×844, 390×740 and 375×667; the excerpts clip by 23 px and 48 px on the two shorter phones, by design).
- **The one-flexible-child rule applies to every fixed or bounded panel box, desktop included, and short landscape windows and 150 % zoom belong in the review matrix.** The phone box got `cols { flex: 1 1 0; min-height: 0 }`, but the desktop box was left unbounded because the matrix (1440×900, 1024×768, 768×1024, 390×844, 390×740, 375×667) had no short window at ≥ 768 px: at 1024×600, 960×540, 932×430 and 844×390 the 100vh pin centred an overflowing panel and the only link fell off-screen. The bound is arithmetic from existing values (`100vh − 2 × 4.5rem − 2.652rem`), and when even the compact content does not fit (the non-excerpt parts are about 300 px against bounds of 244 and 204) a short-height tier has to drop content, as the phone does. A desktop box with a `max-height` but no definite height also needs `flex: 0 1 auto` on its flexible child, not `1 1 0`, or it collapses when nothing clamps it.
- **A scrubbed tail on one subject is still a half-built rest frame: make it a positional safety cut plus a timed leave.** The last planet's 0.77 → 0.90 scroll scrub could rest at half opacity beside a fully lit phone panel. It is now a 0/1 target (`PLANET_LEAVE_AT` 0.80) eased by a `dt` follower that snaps while hidden, and the camera-safety job moved to a separate positional cut (cp ≥ 0.90, true on the first frame even with dt = 0). The price, accepted by the owner, is that a phone (pin to 0.858) no longer shows the planet at its pin release.
- **Extract an effect when its behaviour is the feature.** The hash arrival is a ten-line effect whose whole job is ordering (not before the tier, once, not again after a demotion, not under StrictMode's double run); inline in `VoyageRoot` it was untestable, as a hook it has a `renderHook` suite.
- **Keyboard focus outlives opacity.** A link that turns `tabindex -1` under an opacity-0 panel stays focused and Enter still follows it; `Worlds` blurs the focused link when its panel goes inactive (confirmed live: PageDown into case 2 moves focus from the hidden link to the body, and the next Tab reaches case 2's link). `Tab` from an Orbit panel skips Worlds until the scroll position is inside it (every Worlds link is `-1` outside its hold) — the same design as `Process`; reaching Worlds by keyboard needs the Dock or a scroll first. Recorded, not changed.
- **Worlds is designed and tested for up to 8 published case studies.** Clearance is verified to N = 8 and each case gets 0.69 / N of the chapter (≈ 86vh at N = 8, ≈ 35vh at N = 20); beyond that the slots get thin and nothing enforces a cap. README says so. The browser review saw 3 cases live and the zero-case state live; 1 and 2 cases are covered by unit tests only.
- **Never run `next build` in a checkout whose dev server is live — build in a scratch worktree.** The dev server left running from plan time (started 11:05) hung at 123 % CPU and stopped responding after a real-tree `next build`; the controller had to restart it. Task 9's build therefore ran in `git worktree add ../portfolio-s5-build HEAD`, removed afterwards with `git worktree remove --force` and `git worktree prune`.
- **A symlinked `node_modules` breaks the Turbopack build — clone it instead.** The first build in the scratch worktree failed at once with `Symlink node_modules is invalid, it points out of the filesystem root`. `cp -c -R <checkout>/node_modules node_modules` (an APFS copy-on-write clone, ≈ 4 s) worked and the build went green. The build also needs `.env.local` in the worktree (it prerenders `/work/placeholder-*` from the local database); it was symlinked, never printed or copied.
- **A direct DB toggle is not visible to an ISR page until a dev restart.** `/voyage` is ISR with `revalidate` 300, so unpublishing the three cases for the zero-case check needed a dev restart to show; they were restored afterwards. Case-study items are keyed by `itemId`, not `_id` (`PUT /api/case-studies/<itemId>`).
